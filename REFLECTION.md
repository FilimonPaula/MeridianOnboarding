# Reflection

Developing Meridian Onboarding gave me valuable experience building a complete full-stack application that combines a React frontend with an ASP.NET Core Web API backend.

Throughout the project, I gained practical experience with REST API development, Entity Framework Core, JWT authentication, role-based authorization, and React. I also learned how to structure a project into separate frontend and backend applications while keeping the code organized through services, DTOs, and reusable components.

One of the biggest challenges was connecting the frontend and backend while ensuring that data was displayed correctly and that authorization rules were respected for different user roles. Implementing CRUD operations, debugging API requests, and handling authentication helped me better understand how the different parts of a web application interact.

Working on this project also improved my planning and time management skills. Balancing development with my regular schedule required me to organize the work into smaller milestones, prioritize tasks, and stay consistent throughout the implementation process.

Another important lesson was the value of documentation. Writing the README and documenting the technical decisions made me think more carefully about the design choices behind the project rather than focusing only on the implementation.

If I started the project again, I would spend more time designing the data model before writing code and I would introduce automated testing earlier in the development process. I would also consider deploying the application after implementing additional planned features.

Overall, this project strengthened both my backend and frontend development skills while giving me valuable experience in planning, building, documenting, and completing a full-stack application from start to finish.

## Challenges

One of the challenges I encountered was implementing role-based functionality while reusing the same React pages for both HR and Employee users. Initially, I considered creating separate pages for each role, but reusing components and conditionally rendering actions based on the user's role resulted in a cleaner and more maintainable solution.
